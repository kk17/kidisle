## 采集策略建议

1. **适合程序化采集（主力）**
   - **按 UP 主 mid 拉取视频列表**：对第一部分的已核实 UP 主名单，用 B 站开放接口（`space.bilibili.com` 对应的 Web API，如 `x/space/wbi/arc/search`，或第三方 bilibili-API-collect 社区文档）按 mid 全量/增量拉视频元数据（BV 号、标题、分区、时长、播放量、发布时间），再按年龄段/主题打标入库。UP 主维度数据稳定、噪音小，是最可靠的管线起点。
   - **番剧页采集**：Numberblocks/Alphablocks 等官方番剧（如 ep4616516）用番剧接口拉分集列表，天然带正片链接。
   - **分区巡检**：知识区「亲子」子分区（/c/knowledge 下）定期抓取热门/最新视频作为补充发现渠道。
   - **片单反查**：第二部分的 B 站站内片单视频/opus（BV16b4y1B7oj、opus 975644603498627075 等）可解析简介/评论里的 BV 号批量导入候选池。

2. **半程序化（需解析 + 人工筛选）**
   - 小花生 / 网易 / 澎湃 / 知乎专栏等图文盘点：抓正文提取 UP 主名与 BV 链接（知乎有反爬，需带 UA/cookie 或用移动端 m.zhihu.com），提取结果仍需人工过一遍「是否儿童向」。
   - 豆瓣豆列：页面结构稳定可爬，但豆列是「条目」而非 BV，需人工映射到 B 站可用视频。

3. **只适合人工整理成种子清单**
   - 所有「待核实」UP 主：先在 B 站搜索确认账号存在、mid、内容性质（官方/搬运/自媒体）与版权风险（Super Simple Songs、CoComelon 等 B 站内容多为搬运，收录需评估版权与链接失效风险），再人工定级为种子。
   - 广电总局季度动画目录：每次公示后人工摘录片名，再回 B 站检索对应正片/UP主。
   - 官方活动页（topic_list）：页面为前端渲染，建议定期人工浏览并摘录少儿专题。

4. **建库顺序建议**：先人工固化一份 ~30 个已核实 UP 主的 mid 种子表 → 程序化拉全量视频 → 用标签规则（标题关键词 + 时长 + 分区）粗筛 → 人工抽检定「年龄段/语言/主题」标签 → 每季度补一次社区片单与官方片单的增量。
